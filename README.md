# Natural-JS 2.0

Natural-JS 2.0 is a TypeScript-first CVC UI framework. It attaches behavior to authored HTML and CSS without imposing a visual design. The repository root contains the unpublished `2.0.0-beta.0` candidate on the `2.0.0-alpha.0` development branch.

Shared Rows supports clean batch loading through `append(values)`, insertion before a stable row ID, movement and independent nested copying through `add(value, before?)`, `move(id, before?)` and `copy(id, before?)`. Append preserves existing identities and edits; add/copy create inserted rows. Value reversion keeps the current order; the [Rows contract](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/data.md) defines identity, notifications and business-key responsibility.

Full 1.x framework coverage is still in progress. Column resize/reorder/show/hide, independent multiple selection and row checks, authored header sorting/filtering, stable row actions, atomic validated paste, variable-height viewport rendering, multi-row authored records and adjacent native cell merging are implemented. Grid also supports native radio/checkbox groups, typed multiple Select values, exclusive row checks, validation timing and first-error reveal. Viewport rendering preserves logical-page checks/paste and one complete focused record while mounting a bounded window. The [Grid contract](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/grid.md) defines `<tbody data-row-template>`, display-only `data-merge` cells, nested fields and physical table ARIA positions. Remaining legacy behavior is required before release preparation; see the [feature completion plan](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/implementation/feature-parity-plan.md) and [coverage ledger](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/implementation/feature-parity.md). A [whole-code review and remediation gate](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/implementation/m13-review-plan.md) follows required feature completion, before personal testing. Proposed feature omissions require one consolidated user decision. Unused or unrelated convenience code is excluded after framework reachability checks.

The [interactive Grid demo](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/grid-demo.md) exercises every implemented Grid option and method; run `npm run example` and open `/m10/demo.html`. Its lower section shares nested records across two-row and three-row layouts with native merging; `/m10/columns.html` tests column state in two independent CVC layouts. The current runtime provides `mountPage`, `createRows`, `createCommunicator`, Form, Grid, List, Select, Pagination, Popup, Tabs, Tree, DatePicker, Notifications, Documents, and `FrameworkError`. A plain Dialog uses authored `<dialog>` markup and native methods. Form/Grid retain nested row-local Select binding and Form-reachable formatter/validator rules; their explicit `render` callbacks accept application-created DOM while ordinary display strings remain text. The [employee example](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/employee-example.md) covers data binding; the [page-container example](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/page-containers-example.md) runs one CVC definition in main content, Popup, and Tabs across two MDI layouts. Start with the [2.0 migration guide](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/migration.md) when moving a 1.x screen. See the [package guide](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/package.md) for the five entry points and the [active plan](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/implementation/current.md) for the release gate.

Grid status filters can show retained deleted rows with editing disabled and an authored Undo action. Native defaults feed an application-owned row factory; row hooks own widget cleanup across updates and viewport release. An authored empty row and the `onBind` completion callback support application messages and counters. `refresh()` retries binding without replacing Rows or discarding drafts. These contracts extend the existing HTML and CVC flow; they add no public utility library or network-loader engine.

The [Tree and DatePicker example](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/tree-date-example.md) connects hierarchy selection and calendar input to a shared Form in two CVC layouts; open `/m11/side.html` after starting the example server.

The new 2.0 source and package use Apache-2.0. The preserved 1.x code, bundles, types, documentation, and LGPL-2.1 license live in `v1/` and are excluded from the 2.0 npm tarball. The original `master` branch remains unchanged.

The Grid demo uses one authored CVC detail page inline and in Popup, validates previous/next and close actions, and shares edits with the table. Frozen row scopes expose logical identity independently of mounted DOM and selection. Authored height controls support pointer and keyboard resizing, while explicit reveal alignment accounts for both sticky edges in the measured viewport.

## Build and check

Run `npm ci`, `npm run build`, `npm run typecheck`, `npm test`, `npm run test:consumers`, and `npm run test:browser` from the repository root. Registry publication is deferred; use the locally packed artifact to test this 2.0 candidate. Browser checks need Playwright binaries installed with `npx playwright install chromium firefox webkit`. `npm run example` starts the authored-HTML Vite fixture.

The generated `build/` output comes from `src/`. Public package paths are explicit in `package.json`. Keep types near their owning module and share a private implementation only when multiple framework roles need identical behavior.
The [application shell example](https://github.com/bbalganjjm/natural_js/blob/2.0.0-alpha.0/docs/v2/shell-example.md) runs the same CVC editor in main content, dynamic document tabs and Popup with shared Form data and persistent notifications; open `/m12/side.html`.
