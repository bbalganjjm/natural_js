## 목적
Natural-JS의 TypeScript 타입 정의(`@types/*.d.ts`)를 **최소/명확/구조화**된 형태로 리팩토링한다. “지금 당장 구현을 바꾸는 작업”이 아니라, **타입 선언만** 개선한다.

## 선행 절차(필수)
- 본 작업은 **진행 전 반드시** `project-0-natural_js-shrimp-task-manager-plan_task` 툴로 작업계획을 수립한 뒤, 그 계획을 기준으로 단계별로 수행한다.

## 작업 컨텍스트(반드시 준수)
- **소스 근거**: 실제 구현은 `src/` (ES5+ 호환, jQuery 3.7.1 기반)
- **타입 위치**: `@types/`
- **엔트리 체인**: `@types/index.d.ts`가 모든 `*.d.ts`를 `/// <reference path=...>`로 연결
- **검증 파일**: `@types/natural_js-tests.ts` (컴파일 통과가 곧 타입 검증)
- **빌드 산출물 금지**: `dist/` 직접 수정 금지
- **외부 의존성 추가 금지**: 새 패키지 추가하지 말 것

## 목표(성공 기준)
- **컴파일**: `npx tsc -p tsconfig.json` 가 에러 없이 통과
- **API 정합성**: `src/` 공개 API와 `@types/`가 불일치하지 않음
- **간결성**: 중복/과도한 주석/불필요한 타입 계층 제거
- **안전성**: `any` 확산 금지(경계에서만 제한적으로 사용). 기본은 `unknown`/제네릭/유니온
- **구조화**: CORE/ARCHITECTURE/DATA/UI/UI.Shell/CODE/TEMPLATE 모듈 경계가 명확

## 비목표(하지 말 것)
- 런타임 구현(`src/`) 변경
- 문서(`docs/`) 대규모 개편
- `dist/` 번들 편집

## 빠른 진단(현재 관찰된 “명확한 수정 후보”)
아래는 **반드시 재검증 후** 수정하되, 리팩토링 과정에서 우선순위를 높인다.
- **`NC.element.toOpts` 반환 타입 부정확**: 구현은 `N(ele).data("opts")` 형태로 보이며 `string` 고정이 타당하지 않다. `unknown | NC.JSONObject | undefined` 등으로 교정 필요.
  - 위치: `@types/natural.core.d.ts` (`toOpts`)
- **`NA.Objects.Controller.BaseObject.caller` 타입 부정확**: `NU.Popup & NU.Tab`(교집합)보다는 실제 호출자 의미상 `NU.Popup | NU.Tab`(합집합) 또는 더 구체적 모델이 적합.
  - 위치: `@types/natural.architecture.misc.d.ts`
- **`N.version` 키 구성의 조건부 존재**: `src/natural.js.js`는 기본 키만 갖고, `src/natural.code.js`/`src/natural.template.js`가 런타임에 `NJS.version["Natural-CODE"]`, `NJS.version["Natural-TEMPLATE"]` 등을 추가한다.
  - 타입은 “항상 존재”로 고정하기보다 **옵션 키(선택 속성)** 또는 **확장 가능 맵**으로 모델링하는 편이 안전.

## 리팩토링 전략(권장 설계)
### 1) 핵심 타입 유틸을 중앙화
- `NC.Primitive`, `NC.JSONValue`, `NC.JSONObject`, 공통 콜백/옵션용 유틸을 한 곳(예: `natural.core.misc.d.ts`)에 모으고, 다른 모듈은 이를 참조한다.
- `any` 대신:
  - 외부 입력/플러그인 경계: `unknown`
  - JSON 레코드: `Record<string, unknown>` 또는 현재 JSON 재귀 타입 유지
  - 데이터 컴포넌트는 `T extends NC.JSONObject` 제네릭으로 확장

### 2) `N()`/`NJS<T>`를 “jQuery 확장” 관점에서 재정의
- `N()`는 jQuery를 확장한 컬렉션을 반환하므로 `interface NJS<TElement> extends JQuery<TElement>`를 기본 축으로 삼는다.
- 현재의 `Omit<JQuery, "select">`/인덱서 등은 실제 사용성/정확성을 기준으로 재검토한다.
- `N(selector, context)` 시그니처는:
  - selector/ready 콜백/엘리먼트/배열/jQuery/NJS 등 실제 입력을 반영
  - 반환은 원칙적으로 `NJS<HTMLElement>` 또는 상황에 따라 제네릭 가능(무리한 정확도보다 안전한 최소 모델)

### 3) 패키지별 공개 API는 “네임스페이스 + 클래스/인터페이스”로 정리
- 전역/정적: `declare namespace N { ... }` (현재 패턴 유지)
- 인스턴스(체이닝): `NJS`에 필요한 메서드만 노출
- 내부/기술부채성 멤버(문서용이거나 내부용)는 `misc` 파일로 밀되, 타입/의미가 빈약하면 `unknown` 처리

### 4) 데이터/UI 컴포넌트는 제네릭으로 1회만 모델링
- 예: `NU.Grid<T>` / `NU.List<T>` / `NU.Form<T>` / `NU.Select<T>` 등
- `data()`/`bind()`/`val()` 반환·입력에 `T`를 반영해 `NC.JSONObject` 남발을 줄인다.

## 작업 절차(Spec → Test → Code → Refactor)
### Step 0. 기준선 확보
1) 현재 상태에서 `npx tsc -p tsconfig.json` 실행해 에러/경고를 기록한다.

### Step 1. 공개 API 인벤토리(소스 기반)
아래 파일을 읽고 “외부 사용자가 직접 호출하는 API”만 추려라.
- `src/natural.js.js` (전역 `N`, `NJS`, 버전/할당)
- `src/natural.core.js`
- `src/natural.architecture.js`
- `src/natural.data.js`
- `src/natural.ui.js`
- `src/natural.ui.shell.js`
- `src/natural.code.js`
- `src/natural.template.js`

산출물(메모/리스트):
- 전역 `N.*` (정적 함수/네임스페이스)
- `jQuery.fn`에 주입되는 인스턴스 메서드(체이닝 API)
- 옵션 객체/콜백 타입

### Step 2. 타입 설계 결정(최소·일관)
- `NJS<TElement>`의 기본 모델을 확정한다.
- 공통 JSON/Selector/Callback 타입을 확정한다.
- 패키지 경계(NC/NA/ND/NU/NUS/NCD/NT)별로 “노출해야 할 타입”과 “숨겨도 되는 타입(misc)”를 구분한다.

### Step 3. 타입 선언 리팩토링(파일별)
- **기존 파일을 유지**하되(가능하면), 중복 타입/정의 위치를 재배치한다.
- 새 `*.d.ts` 파일을 추가해도 되지만, 반드시 `@types/index.d.ts`의 reference 체인을 갱신한다.
- 우선순위:
  1) `@types/natural.js.d.ts` (N/NJS의 중심)
  2) `@types/natural.core*.d.ts` (공통 유틸)
  3) `@types/natural.architecture*.d.ts`
  4) `@types/natural.data*.d.ts`
  5) `@types/natural.ui*.d.ts`
  6) `@types/natural.ui.shell*.d.ts`
  7) `@types/natural.code*.d.ts`, `@types/natural.template*.d.ts`

### Step 4. 타입 테스트 갱신
- `@types/natural_js-tests.ts`에 “리팩토링으로 바뀐/강화된 부분”의 **최소 사용 예**를 추가한다.
- 테스트는 예제 코드가 아니라 **컴파일로 검증되는 스모크 케이스**여야 한다.

### Step 5. 검증 & 정리
- `npx tsc -p tsconfig.json` 통과 확인
- `any`가 새로 확산되지 않았는지 확인
- reference 체인이 깨지지 않았는지 확인
