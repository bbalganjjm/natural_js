## 구현 전략(fetch 변환 설계)

### 1) NA.ajax 래퍼 구현
```javascript
// Line 28 교체
static ajax = function(options) {
    // jQuery.ajax 옵션을 fetch 옵션으로 변환
    // - type → method
    // - contentType → headers['Content-Type']
    // - dataType → Accept 헤더
    // - data → body (POST/PUT) 또는 URL 파라미터 (GET)
    // - cache → cache 옵션
    // - async → 무시(fetch는 항상 비동기)
    // - crossDomain → mode: 'cors'
    
    // xhr 객체 호환성을 위해 Promise + abort 메서드 포함 객체 반환
    // - then/catch/done/fail 체이닝 지원
    // - abort() 메서드 구현(AbortController 사용)
    
    // beforeSend, success, error, complete 콜백 처리
    // - beforeSend: fetch 호출 전
    // - success: response.ok && 데이터 파싱 성공
    // - error: response.ok === false 또는 네트워크 에러
    // - complete: finally 블록
};
```

### 2) 옵션 변환 맵핑
| jQuery.ajax 옵션 | fetch 대응 |
|---|---|
| type: "POST" | method: "POST" |
| contentType | headers["Content-Type"] |
| dataType: "json" | Accept: "application/json" + response.json() |
| dataType: "html" | Accept: "text/html" + response.text() |
| data (POST) | body: JSON.stringify(data) |
| data (GET) | URLSearchParams → URL |
| cache: false | headers["Cache-Control"]: "no-cache" |
| crossDomain: true | mode: "cors" |
| beforeSend(xhr, settings) | fetch 전 호출, settings는 fetch 옵션 |
| success(data, textStatus, xhr) | response.ok 성공 시 호출 |
| error(xhr, textStatus, e) | response.ok 실패 또는 네트워크 에러 |
| complete(xhr, textStatus) | finally 블록 |

### 3) xhr 객체 호환 레이어
```javascript
const xhrCompat = {
    readyState: 4,
    status: response.status,
    statusText: response.statusText,
    responseText: text,
    responseJSON: json,
    getResponseHeader: (name) => response.headers.get(name),
    abort: () => controller.abort(),
    // Promise 메서드
    then: (resolve, reject) => promise.then(resolve, reject),
    done: (callback) => promise.then(callback),
    fail: (callback) => promise.catch(callback),
    catch: (callback) => promise.catch(callback)
};
```

### 4) 필터 순서 유지
- `NA.comm.initFilterConfig()` (Line 87~139) 로직 그대로 유지
- `submit()` 내부 필터 호출 순서 보존:
  1. beforeInitFilters (Line 52~62) - 생성자
  2. afterInitFilters (Line 159~164) - submit() 시작
  3. beforeSendFilters (Line 168~177) - ajax 호출 직전 → fetch 호출 직전
  4. successFilters (Line 179~193) - 성공 응답
  5. errorFilters (Line 255~263) - 에러 응답
  6. completeFilters (Line 275~283) - 항상 실행

### 5) 특수 기능 호환

## 주의(중요)
- **jQuery 의존성 제거는 하지 말 것**: DOM 조작(`jQuery.extend`, `jQuery(...)`, `obj.html()` 등)은 그대로 유지
- **fetch polyfill 불필요**: 모던 브라우저 타깃, IE11 지원 시 외부 polyfill 사용자가 추가
- **abort 기능**: `AbortController` 사용(IE11 미지원이지만 프레임워크는 ES5+ 구문만 보장, 런타임 기능은 브라우저 의존)
- **async 옵션 무시**: fetch는 항상 비동기, jQuery.ajax의 `async: false`는 deprecated이므로 경고만 출력하고 무시
